Constraints

One of the key innovations in Sketchpad is the use of constraints to specify how the different graphical elements in a picture — lines, arcs, points, and so on — should be positioned relative to one another. As illustrated by the interactive Sketchpad re-implementation shown in the Sketchpad Demo section, these constraints are not simply static descriptions, but dynamic — the system readjusts the picture as needed to keep the constraints satisfied.

Here are examples of Sketchpad constraints:

  • A line should be horizontal or vertical
  • A point should lie somewhere on a line
  • Two lines are parallel
  • Two points should have the same x and y coordinates

A constraint in Sketchpad is represented by an error function whose value is 0 if the constraint is satisfied. (1) Importantly, the value of the error function is not simply 0 if the constraint is satisfied and 1 if it is not, but instead becomes larger the "less satisfied" is the constraint. So the error for a horizonal line constraint is just the difference between the y values of the two endpoints of the line. If the line is exactly horizontal, the y values will be the same and the error will be 0; the further it is from being horizontal the larger will be the difference in the y values. Similarly, the error for a point-on-line constraint is the distance from the point to the nearest position on the line.

(1) A technical point: actually a constraint that removes one degree of freedom is represented by an error function, as noted above; but a constraint that removes two degrees of freedom is represented using two different error functions. For example, a constraint that two points have the same x and y coordinates removes two degrees of freedom and would have two error functions, one for the x coordinates and one for the y coordinates.

Here are three key benefits of this way of representing constraints:

  1. It doesn't say anything about how to satisfy the constraint or how it interacts with other constraints; it just describes the constraint.
  2. The use of the error function means that Sketchpad can handle inconsistent constraints in a reasonable way, by trying to minimize the overall error, rather than just failing. This error function will also prove critical for the constraint solver.
  3. The simplicity of this representation made it very easy for Ivan to add additional constraints to Sketchpad.

Constraint Satisfaction

Alex Warth wants to talk about how we don't update the value of the variable such that the error is minimized in one step. We do it a little at a time, to prevent wild oscillation while the solver is working. Again, Alex will find a succinct way to say this and (crucially) see if he can find any reference to how Ivan actually tackled this problem in Sketchpad

Given a set of constraints, Sketchpad needs a way to find a solution to them. The principal workhorse for this is relaxation, a technique that was originally developed in the pre-computer era for various engineering applications, such as analyzing loads in truss networks. Here's how it works in Sketchpad. We consider each of the constrained variables in the picture, one at a time. For each variable, we try to find a new value that (approximately) minimizes the sum of the squares of the errors on that variable. We go through all the variables, and then repeat. Keep going until there is a negligible change in the overall error.

Figure 3 demonstrates this process. Each of the lines in the hexagon is constrained to have equal length, and their endpoints are constrained to lie on a hidden circle. Click on the figure. Each time you click, the demo picks the next point to relax, and finds a new position for it that minimizes the errors in its constraints. By the time you've clicked once for each point, though, the solution found for the first point no longer minimizes the errors, since the other points have moved since! So keep iterating (clicking) until the points no longer move. (The hexagon is one of the examples in Chapter 1 of Ivan's dissertation.)

FIGURE 3

[Figure 3 - interactive demo here with honeycomb figure that starts out with irregular lengths for each of the lines. On each click, highlight one of the points and animate moving it to the solution that minimizes the errors just for that point.]

Relaxation was a slow algorithm when implemented on the TX-2. In response, Ivan also implemented the one-pass method. For this method, Sketchpad tries to find an order in which to compute the values of the variables in a drawing in just one pass; if it can do that, constraint satisfaction is much much faster. To do this, Sketchpad looks for a variable v1 that has so few constraints on it that a new value for it can be found that satisfies all those constraints. Ivan calls this a "free" variable. We can then temporarily ignore those constraints since we know we can satisfy them by computing a new value for v1. This may let Sketchpad identify a second variable v2 as free, and so on through vn. Then, to satisfy all the constraints, Sketchpad determines the values of the variables in the reverse order: first vn, then vn-1, and so forth through v1.

Figures 4 and 5 demonstrate the one-pass method and its benefits. Both figures consist of a chain of lines, each constrained to have a given length. The endpoint of the last line (p6) is constrained to be at a fixed location. However, Figure 4 uses relaxation, and Figure 5 uses the one-pass method to satisfy the constraints. Try clicking repeatedly in Figure 4. On each click, the demonstration will find a new position for a point that minimizes the errors for the constraints on that particular point. The demonstration will converge on a solution, but it takes many clicks. Now try clicking on Figure 5 — for that figure, we found an order in which to compute the point positions that let the system compute their positions in one pass, namely p6, p5, p4, p3, p2, and finally p1.

Merging

Sketchpad supports a "merge" operation that allows two objects of the same type to be combined into a single object. For example, suppose we have a line segment with endpoints p1 and p2, and another with endpoints q1 and q2. We then merge p1 and q1, so that they are replaced with a single point. Thereafter the line two line segments are connected.

Merging p1 and q1 is similar in many respects to constraining p1 and q1 to be equal, but there are some important differences. Pragmatically, merging significantly simplifies constraint solving, since there are fewer constraints to be solved. It also reduces storage requirements. The semantics are different as well: if there is an unsatisfied constraint on each of the objects being merged, after merging there will be only one unsatisfied constraint contributing to the combined error; whereas if the two objects were constrained to be equal rather than merged, there would be two such constraints. Further, if the merged point p1/q1 were deleted, this would require that both lines be deleted; but this wouldn't be the case if they were just constrained to be equal.

Merging doesn't apply only to points -- other Sketchpad objects could be merged as well, for example two lines or two arcs. Merging is recursive, so that if two line segments are merged, their corresponding endpoints are merged as well.

Making Multiple Drawings from an Original

Sketchpad provides two distinct ways to make multiple drawings from an original: one is copying; the other is defining a master and making instance of that master.

Copies

When a drawing is copied, the copy has duplicates of all of the points, lines, constraints, and so on that were in the original. The copy has the same topology as the original, so that for example if two line segments share a common endpoint in the original, the copies will as well. Once the copy is made, the original and the copy have no further connection. The user can make further edits to the original, with no effect on the copy; and can also make edits to the copy with no effect on the original.

Copying thus provides total flexibility, but without the ability to have changes in the original reflected in the copies. The copy also requires just as much storage as the original (and remember, storage was at a premium on the TX-2).

Masters and Instances.

Sketchpad provides another way to make multiple drawings from an original: by declaring the original to be a master. Once this is done, as many instances of the master as needed can be created. The internal structure and shape of an instance is completely fixed: the instance can be translated, rotated, and scaled, but otherwise not changed. However, in contrast to copies, an instance retains a connection to its master, so that if the master is updated, the instance is immediately updated as well.

To allow instances to be connected somehow to other parts of the overall drawing, one or more points in the master can be designated as attachers. When making an instance of the master, Sketchpad also creates copies of the attacher points. These will be real points in Sketchpad's memory, and can be constrained or merged with other points in the diagram. However, the attacher points are also automatically given constraints that each attacher point in the instance must have the same relation to the position of the instance as does the corresponding attacher in the master. Other kinds of objects, for example lines, can be designated as attachers as well.

In terms of storage requirements, an instance only requires a fixed amount of storage to store the translation, rotation, and scaling information, plus storage for the attachers, no matter how complex is the master.
